## Saga 1 — bg-submit print delay (3 commits)

**Symptom**: first PAY → ticket took 45 s. Subsequent prints 3-5 s.

**Investigation timeline**:
1. Disabled `posa_allow_submissions_in_background_job` → instant print but lost async submit. Re-enabled.
2. Perf-wrap timing showed 45 233 ms gap between `submit_invoice end` and `get_html_and_style start`.
3. Root cause: `socketStore.waitForPostSubmitPayments(name, 45 000)` waited 45 s for a realtime event that never arrived.

## Saga 2 — QZ Tray "Cannot verify trust - Invalid Signature" dialog (8 commits)

**Symptom**: every session, QZ Allow/Block dialog on first print + first sale took forever.

**Investigation timeline** (red-herring chain):
1. Suspected envelope-shape check too strict → loosened then dropped entirely.
2. Suspected SHA512+PKCS1v15 algorithm mismatch with QZ Tray Java side → verified via Python roundtrip that backend signing matches QZ Tray's `Cert.isSignatureValid(SHA512, sha256Hex, sig)` flow.
3. Suspected qz-tray.js v2.2.5 pre-hashes with SHA256 before calling signaturePromise; backend signs SHA512(sha256Hex) — verified this is correct via reading the JAR's `qz/auth/Certificate.class`.
4. Console probe revealed actual cause: `sign_message → 403 Forbidden`. Operator (Jennifer Corona) had Sales User / Sales Manager but NONE of `_QZ_SIGN_ROLES` (POS User, POS Manager, POS Awesome Supervisor, System Manager). SPA got empty sig → qz-tray.js sent unsigned call → QZ Tray showed trust dialog.

**Commits**:
| Hash | Role | Verdict |
|---|---|---|
| `2320904f` | New POS Profile `posa_qz_cut_after_print` field + ESC/POS cut command appender | Useful, keep |
| `6bb4d875` | Loosen envelope-check to accept unprefixed `qz-tray.js` calls | **Superseded** by `9d2333dd` |
| `def48c01` | Cut command hex flavor (vs plain → printed as garbage chars) | Useful, keep |
| `db8d40ea` | Pre-fetch cert into `cachedCertificate` before `qz.websocket.connect()` so first signed request has cert ready | Useful — improves handshake timing |
| `9d2333dd` | Drop envelope-shape check entirely; rely on role gate + 16 KB length cap | Useful, keep |
| `b4adb905` | Diagnostic probe (`[QZ-SIGN]`/`[QZ-WS]` console logs) | Diagnostic-only; cancelled in `b902e860` |
| `1ac0d77d` | **ROOT FIX** — add Sales User + Sales Manager to `_QZ_SIGN_ROLES`. Reason: POSAwesome's permission model gates POS access via POS Profile membership, not roles; operators sell with Sales roles only | Permanent — solves the dialog |
| `b902e860` | (a) Drop diagnostic probe (b) SW skip caching `.woff/.woff2/.ttf/.eot/.otf` to break recurring "broken font" pathology | Useful, keep |

**Lesson**: the P0 hardening of `sign_message` (added before today) was over-tightened — assumed all POS users have POS User role; in reality Doco's operators don't. Defense layers retained: role allowlist (broader), 16 KB cap, POST-only, login-required.
